# 扫描与发现 模块测试观点

## 1. 基本信息
- 测试对象：skill-doctor「扫描与发现」功能模块
- 模块编号前缀：**SD**（Scan & Discovery）— 本模块所有测试观点、测试用例编号均以 `SD-` 开头，跨模块引用时避免歧义
- 模块范围：
  - 技能发现：扫描已安装技能（`scanSkills`）、探测 Agent 平台（`detectAgents`）、解析与合并扫描路径（`resolvePaths` / `scanSources`）
  - 技能解析：解析单个 SKILL.md（`parseSkill` / `extractTriggers` / `provenanceCache`）
  - 技能详情：查看单个技能（`show` 命令）
  - 健康检查编排：统一健康检查流水线（`runHealthCheck`）
- 涉及核心源码：
  - `src/discovery/resolvePaths.ts`、`src/discovery/scanSkills.ts`、`src/discovery/detectAgents.ts`
  - `src/parsing/parseSkill.ts`、`src/parsing/extractTriggers.ts`、`src/parsing/provenanceCache.ts`
  - `src/config/scanSources.ts`
  - `src/application/runHealthCheck.ts`
  - CLI 命令：`scan`、`show`（`src/cli/index.ts`）
- 测试目的：验证多平台技能发现的正确性、边界处理能力、扫描路径解析的准确性、SKILL.md 解析的健壮性、以及编排流水线的稳定性（含中断信号）

## 2. 测试观点

| 编号 | 测试观点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| SD-TP-01 | 平台路径发现正确性 | 各内置平台适配器（claude/cursor/copilot/codex/gemini/windsurf/trae/opencode/kiro/openclaw/hermes）的 global/project 内置路径能否被正确解析并打上正确的 platform/scope/installSource/confidence 标签 | 高 |
| SD-TP-02 | 技能目录识别规则 | 目录是否被判定为"技能"的规则：必须存在 SKILL.md 才算技能；只有 README.md 等其他 .md 不算；多个 .md 共存时优先选 SKILL.md | 高 |
| SD-TP-03 | 目录递归边界 | 对 references/assets/scripts/node_modules 等支持子目录不递归产生额外技能条目；隐藏子目录（以 `.` 开头）整体跳过；非隐藏的自定义收集目录（如嵌套 `skills/skills`）应继续递归 | 高 |
| SD-TP-04 | Cost-only 路径开关 | `includeCostPaths` 为 false（默认）时不扫描仅用于成本估算的路径（如 AGENTS.md 在 copilot/windsurf 下的 cost-only 场景）；为 true 时纳入 | 中 |
| SD-TP-05 | 多平台共享文件去重/复用 | 同一文件（如 AGENTS.md）在多个平台适配器中都声明监听时，应按平台各自产出一条记录而非漏报/去重丢失 | 中 |
| SD-TP-06 | Override 文件优先级 | 同目录下存在 `AGENTS.override.md` 与 `AGENTS.md` 时，Codex 适配器应优先使用 override 文件而不是默认文件 | 中 |
| SD-TP-07 | 用户自定义路径（extraPaths） | `paths.extra` 配置的自定义目录能被扫描，platform 标记为 unknown、confidence 为 low；支持 `~` 展开与通配符 `*` 展开（含多段通配符、无匹配时返回空） | 高 |
| SD-TP-08 | scanSources 配置驱动覆盖 | 用户在 `~/.skill-doctor/config.json` 中对 `scanSources` 的 builtin 覆盖（enabled、path 等）与新增自定义源，应按 id 合并生效，并正确反映 `origin`（builtin/override/user）与 `status`（exists/missing） | 高 |
| SD-TP-09 | Agent 平台探测（detectAgents） | 是否存在 project 级配置优先于仅有 global 级配置进行 recommended 判定；未检测到任何已知配置路径的平台不应出现在结果中 | 中 |
| SD-TP-10 | 不存在路径的容错 | 待扫描目录不存在时不抛异常，返回空结果而非报错中断 | 高 |
| SD-TP-11 | SKILL.md 元数据解析正确性 | frontmatter 中 name/description/author/repository/when_to_use/paths/globs/applyTo 等字段的解析准确性，包括内联数组、块级标量（`>` 折叠 / `|` 字面量）语法 | 高 |
| SD-TP-12 | 字段回退优先级 | name/description 在缺失时的回退链：frontmatter → 目录 metadata 文件（manifest.json/meta.json/metadata.json）→ 正文 Heading/Description 小节 → 文件名兜底 | 高 |
| SD-TP-13 | 触发词（triggers）提取完整性 | "When to Use"/"Trigger" 小节下的 bullet 列表、frontmatter 的 when_to_use/paths/globs/applyTo/description 均应汇总进 triggers 且去重 | 中 |
| SD-TP-14 | 来源溯源（provenance）优先级 | repository/author 解析顺序：git 仓库信息 → 目录 metadata 文件 → frontmatter → provenance 缓存 → （配置 LLM 时）LLM 提取；不应让扫描工作区自身的 git 信息"泄漏"给技能 | 高 |
| SD-TP-15 | provenance 缓存复用与持久化 | 相同技能路径的 provenance 结果应可从缓存命中，避免重复调用 LLM；缓存文件读写需兼容 BOM、损坏 JSON 等异常情况 | 中 |
| SD-TP-16 | 空文件 / 非法内容处理 | SKILL.md 为空文件（仅空白）时应被跳过（parseSkill 返回 null），不应产生半成品技能记录 | 中 |
| SD-TP-17 | 健康检查流水线编排 | `runHealthCheck` 按 discovering→conflicts→audit→context→grouping 阶段顺序产出进度事件，且中断信号（AbortSignal）在合适的检查点生效并抛出可识别的 AbortError | 高 |
| SD-TP-18 | scope 过滤 | `scan --scope project\|global\|all` 与 `show` 对最终技能列表的 scope 过滤是否准确；非法 scope 值应报错退出 | 高 |
| SD-TP-19 | show 命令行为 | 指定技能名存在时返回详情（含 relatedSkills、可选 whenToUse）；技能名不存在时报错并以非零码退出 | 高 |
| SD-TP-20 | 平台别名解析 | CLI/探测中平台别名（如 claudecode -> claude）能否正确映射到标准 platform 值 | 低 |
| SD-TP-21 | JSON / 终端双模式输出一致性 | `--json` 输出的结构化数据（summary/skills/duplicates/conflicts）与终端渲染在同一份扫描结果下应保持数据口径一致 | 中 |

## 3. 覆盖建议
- 优先覆盖高频核心链路：resolvePaths（跨平台路径解析）→ parseSkill（元数据解析）→ scanSkills（整合）→ scan/show 命令输出。
- 对目录识别边界（SD-TP-02、SD-TP-03）与 provenance 优先级（SD-TP-14）增加针对性的边界与反向用例，历史上这两类最容易因平台适配器新增而回归。
- 对 scanSources 用户配置覆盖（SD-TP-08）与 detectAgents（SD-TP-09）保留至少一组正向与一组反向（错误配置校验）用例。
- 健康检查编排的中断信号（SD-TP-17）建议补充自动化用例验证 AbortError 能否正确冒泡而不是被吞掉。
