# 上下文成本分析 模块测试观点

## 1. 基本信息
- 测试对象：skill-doctor「上下文成本分析」功能模块
- 模块编号前缀：**CC**（Context Cost）
- 模块范围：
  - Token 估算：多平台计费模式、预算评级、Tokenizer 选择（`estimateContextCost` / `tokenCounter`）
  - MCP 成本分析：实时工具列表探测（`scanMcpServers` / `discoverMcpTools`）
  - Codex 上下文分析：配置驱动扫描、资源过滤与范围、插件缓存盘点（`scanCodexContext` / `codexContextConfig` / `scanCodexPluginCache`）
  - Codex 资源控制：启用/禁用技能、MCP 服务与工具、插件（`codexControls`）
  - CLI 命令：`cost`、`context`、`context enable|disable`
- 涉及核心源码：
  - `src/context/estimateContextCost.ts`、`src/context/tokenCounter.ts`
  - `src/context/scanCodexContext.ts`、`src/context/codexContextConfig.ts`、`src/context/scanCodexPluginCache.ts`、`src/context/codexControls.ts`
  - `src/mcp/scanMcpServers.ts`、`src/mcp/listMcpTools.ts`
  - `src/application/runHealthCheck.ts`（context 阶段的 MCP 工具发现复用）
  - CLI 命令：`cost`、`context`（`src/cli/index.ts`）
- 测试目的：验证 token 成本估算在各平台/各资源类型下的口径正确性、预算分级与失败退出码、Codex 配置合并与资源控制的读写正确性、MCP 工具发现在多种传输协议下的可靠性

## 2. 测试观点

| 编号 | 测试观点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| CC-TP-01 | Tokenizer 计数正确性 | OpenAI tokenizer（默认 gpt-4o/o200k_base）与近似 tokenizer（chars/4）的计数结果、元数据（mode/model/encoding/fallback）是否正确；未知模型名应回退到 o200k_base 并标记 fallback | 高 |
| CC-TP-02 | 技能元数据计费（非全文） | Claude/其他平台的技能类资源按"元数据"（description+triggers，非完整正文）计入 startup 预算，避免长正文膨胀 token 税 | 高 |
| CC-TP-03 | Always-on 文件全文计费 | AGENTS.md 等 always-on 文件按完整原始内容计入 always-on 预算类别 | 高 |
| CC-TP-04 | 按平台的成本策略分类 | 不同平台（cursor 规则/copilot 指令/copilot prompt/windsurf 规则触发方式/未知平台默认策略）应映射到不同 activation/budgetScope/kind 组合 | 高 |
| CC-TP-05 | Manual-only / file-scoped 资源不计入启动预算 | `disable-model-invocation`、cursor rule（glob 触发）、copilot instruction 文件等条件激活或手动激活资源，`estimatedTokens` 应为 0，但 `activationEstimatedTokens` 仍反映真实成本 | 高 |
| CC-TP-06 | Codex Skill List 官方上限聚合 | 多个 Codex 技能的元数据文本会被聚合并按官方 8000 字符上限（unknown context window 场景）截断计费，产出独立的 `codex-skill-list` 聚合项，个体技能项本身不重复计入总量 | 高 |
| CC-TP-07 | 禁用资源不计入总量但单独统计 | `enabled:false` 的技能/MCP/插件资源应从 `items`/`summary.totalEstimatedTokens` 中排除，同时出现在 `disabledItems`/`summary.disabledEstimatedTokens` 中 | 高 |
| CC-TP-08 | 预算分级与超支判定 | `gradeCost` 按总量/预算比值分级 A-F；`--budget-tokens`/`--platform-budget` 独立生效，per-platform 预算可单独触发 overBudget 而不影响未超支平台 | 高 |
| CC-TP-09 | MCP 服务器 Token 估算 | 发现的 MCP 工具列表（含名称/描述/schema）计入成本文本；发现失败（`toolDiscoveryStatus:'failed'`）时不计入 token 且给出对应 recommendation | 高 |
| CC-TP-10 | MCP 工具发现三种传输协议 | stdio 子进程、streamable HTTP、legacy SSE 三种协议均能正确发现工具列表；不可达服务器应返回 failed 状态而非抛异常 | 高 |
| CC-TP-11 | MCP 私密信息脱敏 | env/header 中的密钥类字段在成本文本序列化后不应明文出现（仅显示 key 名 + `<masked>`） | 高 |
| CC-TP-12 | Codex 配置加载与合并 | 内置 codex-config.json + 用户 `~/.skill-doctor/codex-config.json` + `--codex-config` 三层配置按 id 合并（override 覆盖同 id，新增 id 追加）；`CODEX_HOME` 环境变量优先于默认 HOME 路径解析 | 高 |
| CC-TP-13 | Codex 资源过滤与范围 | `--resource agents/skill/mcp/plugin/memory` 与 `--scope project/global` 精确过滤；非法 resource 值应报错退出 | 高 |
| CC-TP-14 | AGENTS.md Override 优先级与链路截断 | 同目录 override 文件优先于 base 文件；project 到 workspace root 的 AGENTS 链路按官方字节上限截断累计 | 中 |
| CC-TP-15 | Codex 技能/插件/MCP 的启用状态解析 | `[[skills.config]]` 路径/名称选择器、`[plugins.<id>]` 表、MCP `enabled` 字段的合并优先级（project 覆盖 global，路径选择器需处理符号链接解析） | 高 |
| CC-TP-16 | Codex 资源启用/禁用写入 | `context enable/disable` 对 skill/MCP服务/MCP工具/plugin 的 TOML 配置写入应幂等（重复禁用不产生 changed，不产生重复表头/数组项） | 高 |
| CC-TP-17 | 不可控资源类型的处理 | AGENTS 与 memory 类型资源不支持自动开关，`toggleCodexResource` 应返回 `supported:false` 且不写入配置文件 | 中 |
| CC-TP-18 | 插件缓存盘点独立于成本 | `scanCodexPluginCache` 读取的插件 UI 元数据（displayName/icon/invocation）始终标记 `countedInContextCost:false`，不应计入 token 总量 | 中 |
| CC-TP-19 | cost/context 命令行为一致性 | `cost` 与 `context` 命令共享同一套扫描与估算逻辑，输出结构应一致（仅命令名称/语义不同） | 中 |
| CC-TP-20 | cost 命令 CLI 参数校验 | `--tokenizer`、`--source`、`--platform`、`--resource`、`--budget-tokens`、`--platform-budget` 的非法值应报错并非零码退出，错误信息含用法提示 | 高 |
| CC-TP-21 | `--include-cache` 使用限制 | `--include-cache` 仅支持 `--platform codex`；且仅支持 `--resource all` 或 `--resource plugin`，其余组合应报错 | 中 |
| CC-TP-22 | cost 默认 scope 与显式路径 | 不传 `--scope` 时默认覆盖 project+global；支持显式项目目录参数覆盖当前工作目录 | 中 |
| CC-TP-23 | `--fail-on-budget` CI 门禁 | 总预算或任一平台预算超支时进程以非零码退出，供流水线拦截 | 高 |
| CC-TP-24 | 平台别名解析（cost 场景） | `--platform claudecode` 等别名应正确映射为标准 platform 并过滤对应资源 | 低 |
| CC-TP-25 | Codex 配置文件格式异常处理 | 用户自定义 `~/.skill-doctor/codex-config.json` 或 `--codex-config` 指向的文件非法 JSON /非对象时应抛出可读错误，而不是静默吞掉或崩溃成难以定位的异常 | 中 |
| CC-TP-26 | Codex 资源 ID 不存在时的错误处理 | `toggleCodexResource` 对不存在的资源 id 应抛出明确错误（`Codex resource not found: <id>`），CLI 层应捕获并以非零码退出并回显该错误信息 | 中 |
| CC-TP-27 | `runHealthCheck` 中 MCP 工具发现的跨阶段复用 | Codex 上下文扫描与顶层 MCP 扫描应复用同一次工具发现结果，避免对同一服务器重复发起真实网络/子进程调用 | 中 |

## 3. 覆盖建议
- 优先覆盖高频核心链路：`estimateContextCost` 的分类逻辑（CC-TP-02~06）→ 预算分级（CC-TP-08）→ CLI cost/context 参数校验（CC-TP-20/21）。
- MCP 工具发现的三种协议（CC-TP-10）已有真实网络/子进程集成测试，属于较重的测试，建议保持现状不要转换为 mock，因为协议握手细节容易在纯 mock 下被忽略。
- Codex 配置合并与资源启用/禁用（CC-TP-12、CC-TP-15、CC-TP-16）是历史上最容易在新增平台特性时回归的部分，需保留正向 + 反向（异常输入）用例。
- 本轮识别到 6 个此前完全没有自动化覆盖的缺口（CC-TP-13 的非法 resource 分支、CC-TP-21 的两条 include-cache 限制、CC-TP-17 中 context enable/disable 非 codex 平台拒绝分支、CC-TP-25、CC-TP-26），已在测试用例文档中补齐脚本。
