## 4. 风险等级和检测类别分别说明什么

等级帮助安排复核顺序，不代表恶意概率或发生次数。当前标准规则的默认映射如下；AI 结果可能按具体语境给出不同等级。

| 等级 | 标准规则中的典型线索 | 人工复核重点 |
| --- | --- | --- |
| 高风险 | Shell 执行指令（`shell-exec`）；删除、清空等破坏性操作（`destructive`） | 运行什么、作用于哪里、是否预览／备份、谁明确授权；高影响行为应先复核再使用 |
| 中风险 | 输出、发送或暴露凭据的描述（`secret-leak`） | 是否涉及真实密钥、接收方和日志、是否只使用脱敏值；实际泄露的严重性可能高于默认规则等级 |
| 低风险 | 外部请求、上传或接口调用的描述（`network-call`） | 目的地、发送字段、必要性和授权；低风险不表示任意数据均可上传 |
| 提示 | 页面用于展示信息缺口等非待处理信息 | 阅读原因、补充证据；不应解释为已经通过安全审查 |

静态模式按词形匹配，可能命中教学示例、禁止性说明或合理操作，也可能漏掉正文中的行为。Shell、网络和认证能力本身都需要结合用途判断。

### 你的环境有安全告警时，如何定位？

本机没有非空安全行，因此不展示虚构告警。遇到真实结果时：

1. 点击安全问题，记录标题、等级、受影响资源、证据片段和建议。
2. 在「证据」处使用 **复制路径**，按完整路径打开文件；同名资源按平台和路径区分。
3. 在编辑器中搜索原始匹配片段，阅读前后段落和引用脚本。片段可能只是一小段命中，当前详情不提供可靠的原文行号；不要把匹配片段当成完整指令。
4. 判断它是要求执行、禁止执行、示例还是引用；再检查目标文件、数据接收方、确认条件和恢复方法。

标准证据和 AI 证据都应回到原文核对。本例接下来演示：没有告警时，如何从资源清单主动开展同样的复核。

本次没有执行摘录命令，也没有读取或创建同意记录；不能记录为“已取得用户同意”或“保护逻辑测试通过”。

**操作：** 搜索 `promptfiles`、`reference`、`cookie`、`profile`，核对哪些本地内容可能成为输入，哪些浏览器状态可能被使用。

![图 7：文件输入、参考图、Cookie 缓存和专用 profile 的原文说明](../../assets/manual/security/07-data-cookie-review.jpg)

**本例看到什么：**

- 第 **105、108 行**描述文件提示词和参考图输入。
- 第 **112–114 行**列出登录、Cookie 路径和浏览器 profile 参数。
- 第 **127、129–130 行**说明首次浏览器认证、Cookie 缓存、可能复用已有调试会话，以及指定专用 profile 的选项。

**有什么帮助：** 人工复核可以形成具体问题：允许输入哪些文件和图片？内容会交给谁？是否使用专用浏览器环境？缓存放哪里、谁能读取？是否会把认证值写入日志？这些问题比笼统地判断“它会联网，所以危险”更有助于安排处理。

**操作：** 从原文引用的 `scripts/main.ts` 继续查文件读取、生成调用，以及 `scripts/gemini-webapi/` 中的上传实现和目标常量。使用编辑器搜索即可，审阅过程中无需运行生成命令。

![图 8：本机脚本的真实行号串起文件读取、生成调用、上传目标和表单 POST](../../assets/manual/security/08-trace-upload-code.jpg)

**本次只读核对到：** `main.ts` 第 **261 行**读取文件内容，第 **461、464–465 行**将参考图参数交给生成调用；`constants.ts` 第 **7 行**声明上传地址；`utils/upload-file.ts` 第 **13、16、18–22 行**的相关条目读取文件字节、构造表单、发起 POST 并允许跟随重定向。

**结果含义：** 已找到从说明到实现的部分证据链，使用前应明确输入、目的地和授权。代码中的 URL 是声明值，不是本次实际通信记录；有读取／上传代码也不能直接证明已经窃取数据。

本次没有完成全部依赖、网络分支、重定向、接收端处理、缓存权限或运行行为审计。人工记录应保留这些待核实项，不给整个 Skill 下“已安全”或“已恶意”的结论。

## 7. 把复核结果转成处理决定

建议每组发现记录：**资源与完整路径、版本／文件标识、原文片段与位置、行为和影响、已有保护、未核实部分、处理决定和验证方法**。

本例可以形成以下记录，而不修改资源：

| 证据与现状 | 当前判断 | 下一步处理思路 |
| --- | --- | --- |
| 文档要求首次使用同意、拒绝后停止 | 有保护要求，实施情况待核实 | 核对宿主执行方式和脚本分支，不能直接将历史同意用于任意新输入 |
| 支持文件／图片输入；部分脚本有上传实现 | 属于需要明确数据边界的能力，尚无本次实际发送证据 | 使用前确认输入类别、目的地、必要性与授权；业务不接受外发时暂停该用途 |
| 文档说明 Cookie 缓存与调试会话复用 | 需要进一步检查认证隔离和缓存权限 | 评估专用 profile、最小权限和凭据处理；不复制认证值到复核记录 |
| 当前标准安全分类为 0 | 标准检测结果，不覆盖上述全部行为 | 保留人工待办，不能因缺少告警跳过复核 |

对于其他真实告警，可按实际证据选择处理方式：

| 复核结论 | 处理思路 | 验证重点 |
| --- | --- | --- |
| 合理且必要的命令／联网 | 写清执行范围、数据与目标，补充相应确认条件 | 实际任务只执行获准范围，拒绝时可停止 |
| 示例或禁止性说明被误报 | 保留完整上下文，记录误报理由；评估更明确的表述 | 必要约束仍存在，不为消除关键词而删掉保护说明 |
| 破坏性步骤缺少保护 | 暂停该步骤，增加预览、备份和明确目标／确认 | 在隔离测试数据中验证保护和恢复方式 |
| 凭据输出或未获准外发得到证实 | 暂停相关行为，修订数据处理；如确有泄露，再安排凭据处置 | 原始凭据不再出现在输出、日志或请求中，核对影响范围 |
| 来源或实现无法确认 | 暂停使用相应能力，继续核对维护源和依赖 | 关键证据补齐后再决定是否启用 |

修改前核对共享使用者和实际链接目标。问题详情中的建议是审阅起点；当前安全问题没有通用的“一键修复”流程，不能用重复资源的删除入口代替安全处置。

## 9. 需要 AI 正文审计时，怎样安排

图 2 展示了本次关闭的 AI 安全审计入口，本篇没有实际运行 AI 审计，也未提供其效果截图。

若后续使用，先确认 analysis 服务的接收方、访问权限和数据政策，并核对将审计哪些文件。AI 审计会尝试发送完整正文；本地、局域网和云端服务都应按实际目的地判断，而不能只依据页面上“本机分析”的提示。

确认相应数据可交给该服务后，在「扫描设置」中开启「AI 安全审计」，保存并重新体检；随后按安全分类复核新增证据。模型服务已保存不等于可用；调用／解析失败、覆盖不全或使用缓存时，不能用空结果证明正文已全部审过。AI 建议仍需对照原文与实际场景，不自动执行模型给出的命令或修复步骤。
