# Codex 优化建议：交互设计

日期：2026-09-18。状态：用户选择第三版，已实现下述首期范围；其余设计条目仍是后续设计，不代表全部已交付。

## 第三版实现范围

- Codex 一级入口「优化建议」，三步流程：看会话开销 → 选择优化 → 验证效果。保留原有固定紫色主题与多 Agent 外壳；静态资源占用降为次级入口。
- 默认读取当前自然月的全部 task，并可切换当前自然周；同一 task 的重复日志去重，采用最新活动记录。明细最多展示 20 行，但周期总计不按这 20 行截断。累计用量来自记录，不等于上下文窗口大小；分页日志可能不覆盖完整历史。默认选择具有可执行建议的会话。
- 首期开放两个目标：项目 `skills.include_instructions=false`、用户 `memories.use_memories=false`。只对调查版本与完整初始头开放；配置层覆盖、来源缺失、版本未知时拒绝写入。
- 展示原始文本 Token 估算及每次响应缓存边界费用区间；默认按内置价格表中最高价模型估算，另提供低调的“按实际使用模型”切换。没有完整用量不虚构数字。沿用内置价格表并显示日期，不是实时定价或订阅账单。
- 实际配置预览、摘要确认、全局影响复选框、原子写入、单键撤销；成功写入仍为待验证。用户需自行新建同项目 Desktop task，页面读取新的 JSONL，核对时间、版本、完整头和配置指纹。
- 界面保存最近一项操作的进度；不包含完整操作历史列表、可调整时间窗、自定义价格表、自动新建 Desktop task、单技能/推荐插件开关。CLI 旧配置写入接口没有扩展为新向导，README 已警示其证据边界。
- 真实本机数据只读浏览器验收；配置写入、撤销、失败与新头验证在隔离临时目录中测试，没有为验收改动真实 Codex 配置。
- 验收文件：仓库根目录 `design-qa.md`。截图保存在本机 `docs/optimization-qa/`，不上传。

## 目标与已有证据

用户进入工具后能回答：这个会话用了多少 Token、按选定价格表折合多少美元、哪些改动能减少上下文、会失去什么，以及改动是否在新会话真正生效。

依据：仓库根目录 `codex-context-block-verification.md` 第 3、8、9 节；当前 `ContextOptimizationPage`、`BenefitPage`、`HistoryControlPanel`；现有浏览器页面 `#/context` 和 `#/context?view=recommendations` 的实际截图。视觉沿用 `web/DESIGN.md` 和 `web/src/theme.css` 的深紫工作台。

当前问题：默认展示静态“每轮固定成本”，用户看不到具体会话的真实消耗；建议前有六项统计与长解释，行动入口落在下方；推荐插件占据建议列表，且“仅此项目关闭全部推荐”与 Desktop 实测冲突；单技能项目级配置仍有写入入口，但调查证明 Codex 忽略这一层规则。

## 信息架构与默认路径

- 一级导航将“上下文优化”显示为“优化建议”，可用建议数量只计算当前版本、配置层和资源目标均受支持的独立操作。当前已有菜单保留，其余导航不扩张。
- 页内三个视图：“优化建议 / 会话开销 / 优化记录”，默认建议。原“收益依据”移入建议详情的展开区。
- 总览放一个“查看优化建议”入口；尚未分析时写“分析可优化项”，不能提前编造数量或金额。
- 默认只读分析本项目当前自然月的全部完整会话，也可切换当前自然周；界面显示覆盖数和时间范围，明细表最多 20 行。选择会话后更新建议来源与验证基线，周期收益仍统计所选周期全部 task。切换项目立即失效旧报告及其操作按钮。
- 以收益与影响引导点击，不使用虚假倒计时、未经测量的节省百分比、把不支持的候选塞进红色数量徽章。

## 首屏内容

标题“优化建议”，副标题“一眼看清开销，选择值得关闭的上下文”。显示项目与 Codex、数据更新时间。

上方紧凑一行：本期全部 task 的总 Token、按默认最高价模型折算的美元成本、可执行建议数；周期按钮可切换本月/本周，旁边保留不抢眼的实际模型计价按钮。成本标签常驻“API 等价估算”，详情说明订阅额度不等于按 Token 付费账单。

主体从第一条建议开始，行内只保留：具体动作、预计收益、影响范围、简短影响、主要按钮。例：

| 动作 | 预计收益 | 影响 | 主按钮 |
| --- | --- | --- | --- |
| 隐藏自动技能目录 | 新会话首轮减少 Δ Token；折算 $L–$U | 仅此项目；模型不再自动看到技能目录 | 查看并隐藏 |
| 停止注入记忆 | 新会话首轮减少 Δ Token；折算 $L–$U | 全部 Codex 项目；未来会话不再自动使用历史偏好 | 查看全局影响 |
| 停用一个低使用技能 | 仅在此版本/来源已有有效控制证据时估算 | 用户级；其他项目也受影响 | 查看并停用，或“查看限制” |

“推荐插件列表无法单独关闭”等项目收进“暂不能直接优化”的折叠区，不计入可执行建议及合计收益。

## 会话开销口径

- 按会话列出日期、标题、模型、输入 Token、其中缓存命中、输出 Token、总 Token、API 等价成本、数据完整度；点击展开每次模型响应。
- 输入已包含缓存输入，不再把缓存数加一次。推理 Token 若属于输出分项，仅作细分，不重复求和。
- 使用响应级唯一记录去重并累加；累计计数只取有效差值/末值，不能与响应记录叠加。父子 task 单独显示，避免继承历史重复计费；工具调用数不当作模型响应数。
- 默认费用按价格表中最高价模型统一估算，未知实际模型也可计入上限；切换“按实际使用模型”后，才按每条日志中的模型分别定价再求和。缺少实际模型、缓存字段或完整用量时显示“— / 部分覆盖”，不能显示 $0。
- 价格表展示来源、版本日期和币种，允许本地用户价格表。设计稿全部标明“示例数据”，不代表当前模型实时价格。
- 会话中的总计属于实测用量；block 长度属于指定 tokenizer 的估算；两者采用不同标签。

## 节省口径

主视觉显示“整段会话预计节省”的周期累计 Token 和金额；所选明细会话的首轮收益在旁边以小字展示，窄屏自动换行。辅助文字展示本期 task、turn 和已记录模型响应数，并注明当前明细会话。默认金额采用最高价模型，切换后显示实际模型口径。累计值是历史模拟，不是实际账单退款。

对输入包含缓存的价格表：成本 = (输入 - 缓存输入) × 未缓存单价 + 缓存输入 × 缓存单价 + 输出 × 输出单价；所有单价按每百万 Token 换算。若供应商有独立缓存写入费用，按其计费定义单列，不能套用同一公式。

对某个响应的移除量 D，输入 I、缓存 C，最多/最少落在缓存中的移除量分别为 min(D,C)、max(0,D-(I-C))；按两端计算估算金额区间。没有可信边界时，只显示“按全缓存/全未缓存假设”，不伪造精确数。

整会话收益仅在能追踪该 block 在各次请求中的存续、截断/压缩与用量记录时做历史模拟。覆盖不完整时标题改为“已覆盖响应累计预计节省”，显示上下文与用量覆盖数；价格不完整时只累加可估价响应，并紧邻金额标明它不是完整会话金额。没有证据时显示未知，不按零处理。WebSocket 首包仅传一次不意味着之后每个响应都不计入历史输入，也不允许直接把首轮差值乘所有响应数。

同时选择整技能目录和单技能时对移除文本求并集，不能重复计入；推荐候选补位时，不把旧候选文本长度计作确定净节省。

新会话验证只能证明目标上下文被移除。界面显示“已验证移除 Δ Token（文本估算）”及“对应 API 等价节省估算”，不把两个不同任务的总成本差当作此次配置的因果收益。

## 控制能力与按钮规则

| 用户动作 | 准确配置与层级 | 当前证据 | 设计决策 |
| --- | --- | --- | --- |
| 隐藏自动技能目录 | 项目 `[skills] include_instructions=false` | Desktop 新 task 验证 | 可提供；明确是隐藏目录，不是卸载或禁止读取所有技能 |
| 停用单技能 | User/SessionFlags `[[skills.config]] path="绝对 SKILL.md 路径"; enabled=false` | Core 验证层级有效；已有报告未给出逐个 Desktop 来源的完整 A/B | 项目级操作移除；只有当前 Desktop 版本/来源经验证且写入用户层获确认后才开放。其余显示验证待补，不承诺有效 |
| 隐藏 Apps 说明 | 用户根级 `include_apps_instructions=false` | Desktop 单变量验证 | 可提供全局操作；隐藏说明不等于停用 Apps |
| 隐藏协作说明 | 用户根级 `include_collaboration_mode_instructions=false` | Desktop 单变量验证 | 可提供高级操作，解释协作指引缺失的影响 |
| 隐藏环境信息 | 用户根级 `include_environment_context=false` | Desktop 单变量验证 | 可提供高级操作；模型失去自动 cwd/date 等提示 |
| 停止注入记忆 | 用户 `[memories] use_memories=false` | Desktop 验证 | 可提供全局操作；不删除记忆、不宣称停止生成记忆 |
| 隐藏延迟工具目录 | 用户 `[features] deferred_tool_world_state=false` | Desktop 正反验证 | 高级操作；不声称工具禁用，说明可发现性影响 |
| 不注入项目文档 | 用户根级 `project_doc_max_bytes=0` | Desktop 验证 | 高影响高级项，默认保留；不把丢失项目规则当普通低风险建议 |
| 隐藏权限说明 | 用户根级 `include_permissions_instructions=false` | Desktop 单变量验证 | 不进入默认节省建议；高级详情明确不改变沙箱/审批机制，但减少模型获知的约束 |
| 单独关闭推荐列表 | `[features] tool_suggest=false; recommended_plugins=false` | Desktop 仍有推荐 | 不提供“关闭”按钮，显示“当前 Desktop 不支持可靠独立关闭” |
| 屏蔽一个推荐候选 | `[tool_suggest] disabled_tools` | 可能补位，不能保证 block 减少 | 不作为节省建议；如保留偏好控制，另名“屏蔽推荐”，不承诺净收益 |
| 关闭插件说明及推荐 | 用户 `[features] plugins=false` | Desktop 验证能去除两个 block | 仅高级“停用插件功能”，列出受影响技能/工具；不伪装成隐藏说明按钮 |

证据需绑定 Codex runtime / Desktop 版本、配置层、来源类型和验证时间；未知版本可降级为需验证。不能因为表中某个旧版本有效就对任何安装环境永久显示“已验证”。

## 确认与验证闭环

点建议打开右侧抽屉，按顺序展示：动作名称 → 预计减少 Token / 美元区间 → 影响范围 → 会失去什么 → 生效时机。原始路径、键值差异和调查证据收在“技术详情”。

当前项目操作默认仅项目。用户级操作常驻“影响本机所有 Codex 项目”，不能默认假装仅当前项目，也不静默扩大范围。隐藏目录的按钮叫“隐藏目录”，停用技能叫“停用技能”，停用插件总功能另行命名。

确认按钮例：“确认隐藏 · 下个新会话生效”。写入后显示“设置已更新，待新会话验证”，主要下一步“检查新会话”，次要“撤销”。旧会话继续保留旧上下文。

普通 Web/CLI 环境不能假定有 Desktop task 创建 API：给出两步提示“在 Codex 为此项目新建 task，发送一条消息”→“检查新会话”；只读自动发现或用户导入 JSONL。仅在集成具备经过授权的 Desktop 创建能力时，才展示“创建验证任务”，并提示该验证任务会消耗模型额度。

候选会话必须晚于操作时间、项目/配置层匹配、非 fork/paginated 增量、会话头完整；对比同一目标 item、有效配置指纹和版本。配置变更、缺失 role、metadata 长度错位、压缩后片段，均不能作为 absent 证据。

状态：未操作 → 配置已更新/待验证 → 已验证移除；如果 block 仍存在，显示“尚未生效”，列出观测证据、恢复入口。只有确有宿主覆盖证据才写“被宿主覆盖”，不凭仍存在直接断言原因。

撤销只恢复本操作修改的键；遇到外部后续改动先提示冲突，不覆盖整文件。已运行会话不会因撤销而改写，下一次新会话再次验证。

## CLI 对应体验

这是待实施的产品契约，不代表以下新命令已存在：`skill-doctor optimize` 默认只读输出会话概览与可执行建议；交互模式可选择建议、展示影响并确认；`--json` 提供相同字段给集成工具。写入与验证分步执行，沿用现有 preview/confirm/undo 的安全机制。

现有 `context blocks --file <session.jsonl>` 可以作为观测入口，但在补齐完整性、新 task 时间、配置指纹及覆盖校验前，不能直接担当“优化已生效”的最终验收。

## 三种布局的共同约束与差异

三种方案共享以上控制能力、收益口径、深紫主题与准确文案，不通过配色来伪装不同方案。

- 建议优先：一级“优化建议”，首屏紧凑会话开销 + 可执行建议列表，右侧抽屉完成确认。适合最低学习成本。
- 会话优先：左边近期会话列表，右边所选会话成本和建议；每个决定都绑定具体会话。适合追查某次任务为何昂贵。
- 引导优化：页内三步“看开销 → 选优化 → 验证”，只展开当前步骤；详细规则折叠。适合首次使用和非开发用户。

## 实施与验收

先补底层 capability registry（版本/层级/目标/影响/证据）、用户级精确写入和撤销，再接 UI；仅改标签不足以满足“真实禁用”。同时补完整会话判定与响应计费去重。

复用当前 ContextOptimizationPage 路由、BenefitPage 报告状态与 API，避免建立平行扫描系统。会话开销、收益估算、操作状态分别提供明确数据字段，保留旧路由兼容。

验收：首次进入一屏看到主按钮；三次点击以内到达某条建议的最终确认；没有建议时不显示虚假收益；不支持项目级单技能禁用；不支持推荐 block 独立关闭；所有全局操作明确范围；父 block/子技能节省不重复；配置写成功仍显示待验证；完整新会话才可验证移除；fork/残缺 header 显示未知；美元缺价显示未知；验证失败和撤销可恢复；390px 窄屏、键盘焦点与可访问状态正常。
