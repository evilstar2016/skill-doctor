# 离线历史收益：实施与验证

日期：2026-09-11。未修改用户 Codex 配置，未运行付费模型对照实验，未提交 Git。

## 已实现

- 无方案 ID 时默认读取全部可读项目历史及归档；显式时间/数量限制保留并披露。CLI 和 UI 使用同一服务端算法。
- 历史使用画像、最新目录、最长主会话分别选择。同一会话的多个 rollout 文件合并，两个目录独立保存时间、路径、行号和 SHA256。
- 解析原生 UserMessage item、response_item、旧 user_message、结构化激活及携带 plugin_id 的工具调用。镜像消息、继承事件去重；先去掉审阅 transcript，再处理 My request，避免把引用内标题当成用户新请求。Skill 读取单列，不当作激活。
- 候选来自注入目录，不由本机 inventory 裁剪。所有目录 alias 用于路径展开；删除 alias 依据保留的历史描述。当前已禁用的 Skill 不丢弃历史成本。未知控制只展示假设潜力。
- 插件逐 ID 配置与双 feature 整块控制分开说明；不调用实际配置写入，不使用 plugins.enabled 代替推荐控制，不隐含授权整组禁用。
- 默认“最新目录 × 最长主会话”与“历史可重建回放”分开。推荐插件按持续可见的每响应计数，不再按一次注入锚点归零。ContextCompaction item 与 compacted 记录都会使回放证据失效。
- 显示用户消息、原生 UserMessage item、turn_id、完成轮次和模型响应的不同计数；首响应、首次交互、逐轮、逐响应缓存上下界和 R/B/U 扣减均保留。子任务用量及模型费用单列。
- JSON/HTML/CSV 导出；页面提供候选、证据位置、逐轮、逐响应明细。原有响应列表不再截掉第 200 条之后的记录。
- 缓存重建场景让首条受影响响应按冷缓存计算，并保证汇总与逐模型费用使用同一个情景。索引升级至 schema 4，避免复用旧的压缩判断。

## 不能据此声称的结论

- 1,825,800 是把最新目录保持可见的假设投射，不是历史实际节省，也不是已经减少的订阅账单。
- 此样本不能重建两块目录同时存在的完整历史请求，历史回放 895 条响应为未知；累计字段中的 0 是已重建子集为空，不是证明历史可省 0。
- 逐 ID 屏蔽可能由其他推荐补位。50 项测试验证的是固定目录删行，不是目标 Desktop 的真实候选重排；实际节省需新会话验证。
- 单 Skill 来源控制未确认时显示 unverified，不声称禁用整个所属插件是安全的。若用户选择整组禁用，仍须核查兄弟 Skill/工具及保留依赖。
- 模型工具调用仅在可明确归属 plugin_id 时计作插件使用；不凭通用工具名猜插件身份。使用画像是可追溯静态证据，不是语义意图分类器。
- 费用仅 628/895 条响应可计价，其余 267 条因价格或适用输入分区不可用而排除；不能把约 USD 0.447821 的可计价子集估算当作整个会话的确定费用收益。
